# Контракты механик `core/mechanics/`

Библиотека мини-игр и механик (прообраз — `mechanics_library_pack_v3`: 15
standalone HTML, 4 движка, контракты). Это фактически зерно общего ядра.

## Главное правило

> **Новые механики добавляем — старые не ломаем.**

Любая колода может зависеть от существующей механики. Изменение сигнатуры или
поведения механики — это изменение контракта, оно затрагивает все колоды.
Поэтому: расширяем обратносовместимо, ломающие изменения — только через явную
миграцию всех потребителей.

## Что описывает контракт механики

Для каждой механики фиксируется:
- какой движок(и) её поддерживает;
- формат входных данных (как колода передаёт контент);
- тип задания из общего набора (`intro / single / multi / pairs / sort / sim`);
- что механика пишет в прогресс.

## Статус

Код механик мигрирует из `mechanics_library_pack_v3` (этап 1 плана рефакторинга,
`../../docs/architecture.md` §9). Сейчас — каркас контракта.

## Реестр механик

### `panorama-hotspots` — панорама с хотспотами
Картинка/панорама (пан+зум или «в размер экрана») + кликабельные точки → карточка
(картинка-герой, заголовок, текст), опц. видео-заставка и звук на хотспот.
- Файл: `core/mechanics/panorama-hotspots/panorama-hotspots.js` (ES5, без зависимостей,
  CSS вставляет сам). Демо: `panorama-hotspots/demo/index.html`. Доки: там же `README.md`.
- API: `PanoramaHotspots.open(scene)` / `.register(id,scene)` / `.edit(scene)` (редактор
  разметки: тап ставит точку, драг двигает, панель отдаёт JSON с координатами в %) / `.close()`.
- Вход: `{image, pan, hint, intro, base, hotspots:[{x,y,title,subtitle,text,image,audio}]}`
  (координаты x,y — в % от изображения).
- Прогресс: не пишет (чистый просмотр). Тип задания — вне набора (обзорный режим).
- Извлечён из `decks/kulturnyy-pasport` (разборы на схеме театра). Обратносовместим,
  самодостаточен, ничего в колодах-потребителях не требует, кроме подключения `<script>`.

### `memory-triples` — мемори по тройкам (и по парам)
Обычное мемори учит одному соответствию; тройка заставляет держать в голове три
представления одного объекта сразу (у «Стран мира» — контур, флаг, название).
Размер группы задаёт колода: `2` — привычные пары, `3` — тройки.
- Файл: `core/mechanics/memory-triples/memory-triples.js` (ES5, без зависимостей,
  CSS вставляет сам). Доки: README рядом.
- API: `MemoryTriples.mount(el)` / `.start()` / `.again()` / `.stats()`.
- Вход: `window.MEMORY_TRIPLES = {items, kinds, perGroup, groups, keyOf, render,
  labels, backHref, onOpen, onMatch, onDone}` — лицо карточки рисует колода
  колбэком `render(host,item,kind)`, механика про содержимое не знает.
- Тип задания — `pairs`. Прогресс **не пишет** (тренажёр-повторение); колода может
  записать свой из `onDone`.
- Эталон — `decks/strany-mira/memo3/` (контур из геометрии `poly`, флаг из base64,
  название из перевода; собранная тройка озвучивается).

### `lines-match` — «верёвочки»: соедини пары линиями
Тап по элементу слева, тап по элементу справа — тянется линия. Тап по концу
уже связанной пары освобождает её для новой связки, без отдельного шага
«отвязать». «Проверить» красит все линии и рамки разом, как проверка целого
разворота, а не пошаговый вопрос-ответ.
- Файл: `core/mechanics/lines-match/lines-match.js` (ES5, без зависимостей,
  CSS вставляет сам, свои переменные `--lnm-*` со значениями по умолчанию —
  хост-страница может переопределить их у предка контейнера обычным CSS).
  Доки: README рядом.
- API: `LinesMatch.mount(container, pairs, opts)` → `{check(), reset(newPairs?),
  destroy()}`. `pairs`: `[[left,right],…]`, строки уникальны в пределах раунда
  (поиск элементов идёт по значению). `opts.onCheck(result)` зовётся из
  `check()` с `{good, total, items:[{l,r,ok}]}`, уже после перекраски.
- Кнопки «Проверить»/«Ещё раз» модуль не рисует — решает вызывающий код.
- Тип задания — `pairs`. Прогресс не пишет сам — очки/награду насчитывает
  колода в `onCheck` (SNS зовёт `reward()` по каждому `items[i]`).
- **Не извлечение** уже существующей «верёвочки» — `type:'lines'` в
  `core/engines/eng-book/engine.js`, вплетённой в реестр упражнений движка
  книг и держащей восемь юнитов «Английского 5». Тот вариант не трогаем:
  риск для готового контента не окупается. Этот модуль — независимая
  реализация того же приёма для движков без общего реестра `checkEx`;
  свести их в один код — задача на будущее, не часть этой правки.
- Эталон — `decks/slovar-na-stsenah`, задание «Верёвочки» в «Занятиях»:
  раунд из открытого банка слов (`drillPool`, как у «Пар»), не привязан к
  одной теме или сцене.

### `assembly-3d` — 3D-конструктор (three.js)
Интерактивная 3D-модель, собираемая по деталям с фактами: сборка → взрыв-схема →
разрез с интерьером → экскурсия-автооблёт → ярлыки-выноски; фирменная сцена
(зимний вечер, PBR/ACES/PMREM, снег, прожекторы, звук).
- Движок: `core/mechanics/assembly-3d/assembly-3d.js` (ES5; three.js r128 UMD из
  `core/vendor/three-r128/`; bloom/GLTF-модули опциональны). Доки: README рядом.
- Контент: страница с фикс-разметкой + `window.ASSEMBLY3D_CONFIG` (детали-строители,
  факты, ярлыки, интерьер, маршрут экскурсии). Эталон — `decks/kulturnyy-pasport`
  (`model3d.html` + `model3d-parts.js`).
- Прогресс: не пишет. Тип — обзорно-игровой режим вне набора заданий.

### `metre` — ритм-решётка (такт = четыре доли)
Фраза раскладывается по тактам и долям; в ячейке — слова, ученик считает слоги.
Кнопка ▶ отбивает счёт и подсвечивает долю за долей — под неё читают вслух.
Идея из методики рэп-метра; педагогическая мишень — **слоговая структура слова**
(частая логопедическая проблема; отхлопывание по слогам под ровный счёт —
стандартный приём коррекции).
- Движок: `core/engines/eng-book` (тип упражнения `metre`). Метроном — Web Audio,
  без ассетов; при отсутствии `AudioContext` (jsdom, старые webview) молча
  пропускается, разметка не страдает.
- Вход: `{type:"metre", bpm, chant, bars:[{cells:[{w:"Every", n:2}, …]}]}` —
  `w` текст доли, `n` число слогов (это и есть проверяемый ответ). Обычно
  2 такта × 4 доли. Слово можно разрезать между долями («I'm wash-» / «ing up in-»),
  тогда `n` считается для куска.
- Проверка: счёт слогов сделан обычными `.tinput`, поэтому `checkEx`/`answersEx`
  работают общим кодом — **отдельных веток в них не потребовалось**.
- Прогресс: как у обычного упражнения (баллы = верно заполненные доли).
- Эталон контента: `decks/angliyskiy-7` — по одному упражнению в каждом из
  10 юнитов, на кричалках года из `teacher/talk.html`.

### `shift` — «Одно слово — другой смысл»
В предложении один слот; в него по очереди встают разные слова, и каждое
**поворачивает смысл**. Верного ответа нет — задание показывает, что грамматика
это выбор, а не ярлык (идея из методики «grammar for writing»: `The house was
haunted` ≠ `My house was haunted`).
- Движок: `core/engines/eng-book` (тип упражнения `shift`).
- Вход: `{type:"shift", sentence:"He is the boy {} sits next to me.",
  options:[{w:"who", mean:"о человеке — нейтральный выбор"}, …], ask:"вопрос классу"}` —
  `{}` место слота, `mean` разбор сдвига смысла по-русски, `ask` опционален.
- Проверка: **балл за исследование** — открыл все варианты, увидел все сдвиги.
  Это первый на платформе тип задания без правильного ответа, поэтому в
  `checkEx`/`answersEx`/`resetEx` заведены отдельные ветки по `reg.type==='shift'`.
  «Ответы» показывают все разборы списком.
- Прогресс: баллы = число открытых вариантов из общего числа.
- Эталон контента: `decks/angliyskiy-7`, юниты 3 (who/which/that) и 10 (should/must/can).

### `ritm` — «Отхлопай» (режим речевых колод)
Слоговая структура под ровный счёт для серии «Речь»: слог загорается под щелчок
метронома, ребёнок хлопает и проговаривает; рядом — эталон диктора.
- Движок: `core/engines/rech-deck-kit` (функции `ritmSides()` / `openRitm()`).
- Вход: **ничего нового не требуется** — слоги берутся из уже размеченного поля
  `syllable` карточки («БЫ-БЫ-БЫ»). Кнопка режима появляется автоматически там,
  где разметка есть; условие — `ritmSides().length`.
- Доступен: Болталки, Бормоталки, Скороговорки, en-chatter, en-tricky, en-twisters.
  Скрыт там, где дефисной разметки нет (Слоги, Фонетика, Азбука, Истории, sluh).
- Прогресс: не пишет (тренировочный режим), 5 карточек за подход.
- Режимы серии обязаны сами открывать модалку (`modal.className='modal on'`) —
  сборки содержимого в `mbody` недостаточно, иначе кнопка нажимается «в пустоту».

### `eng-vocab` — фото-словарь класса (страница, не упражнение)
Ключевые слова юнита настоящими фотографиями: квадратная сетка, нажатие на фото
проговаривает слово (браузерный синтез, без mp3 — словарь должен работать в любой
колоде без озвучки). Отдельная страница класса, не тип упражнения учебника.
- Движок: `core/engines/eng-vocab/` (`vocab.js` + `vocab.css`). До выноса страницы
  5 и 6 классов были двумя копиями одного кода, 7-й стал бы третьей.
- Колода приносит: `window.VOCAB_CONFIG` (`grade`, `units`, `back`, опц. `lead`),
  `vocab/data/words.json` (источник правды) и `vocab/data/fallback.js` (та же копия
  в `window.VOCAB_FALLBACK` — под `file://` fetch запрещён).
- Формат слова: `{word, ru, img:"../img/voc-u<N>-<slug>.webp", credit:{author,license,page}}`.
- Картинки: **фотобанк, не генерация** — 360×360 WebP, забор
  `tools/python/fetch_vocab_photos.py <slug> candidates|pick` по
  `vocab/data/spec.json`. Между шагами обязателен просмотр контактного листа:
  поиск регулярно приносит не тот предмет, а квадратный кроп добивает то, что
  на превью выглядело нормально.
- Прогресс: не пишет (стена слов для просмотра и озвучки).
- Собрано: 5 класс (36 слов), 6 класс (39), 7 класс (40).

### `anki` — выгрузка карт во внешнее приложение (не наш движок)
Единственный модуль курса, который НИЧЕГО не рисует сам: он отдаёт наши карты
файлами `.tsv` для приложения Anki, чтобы ученик повторял в том тренажёре,
которым уже пользуется. Наш собственный тренажёр интервального повторения —
соседний модуль `srs`, и он не заменяет этот: SRS работает внутри продукта и
хранит прогресс у нас, Anki уносит карты наружу.
- Страница: `decks/angliyskiy-5-9/anki/index.html` — инструкция по импорту и
  ссылки на выгрузки.
- Данные: пять `.tsv` рядом со страницей — `eng-vocab-5`, `eng-vocab-6-7`,
  `eng-grammar`, `eng-reference`, `eng-idioms` (399 карт суммарно). Формат —
  колонки, разделённые табом, как ждёт импорт Anki.
- Словарные колоды собираются из словаря года: `node tools/node/build-anki.js
  <deck> <out.tsv>` читает `data/appendix.json` — тот же список, по которому
  живёт приложение-тетрадь, поэтому бумажный и цифровой словари не разъезжаются.
  Генератор снимает дубли: Anki при импорте молча склеивает карты с одинаковым
  первым полем, и «пропавшие» потом не найти.
- У словаря 5 класса определений нет, только перевод — английское определение
  для первого года обучения сложнее самого слова. У 6–7 определение есть.
- Прогресс: не пишет — повторение живёт во внешнем приложении.
- Модуль общий для 5–9 и **ссылка на него обязана быть во всех кабинетах
  классов**: до 25.07.2026 её не было в кабинете 5 класса (как и на `cards`,
  `srs`, `reading`) — из пятого класса к общим модулям было не попасть.

### `activities` — карточка занятия с оценками значками
Занятие показано фотографией и **пятью оценками значками** (сколько стоит,
насколько сложно, где, с кем, сколько времени), по три уровня в каждой шкале.
Значки читаются без слов, поэтому по ним можно спрашивать и спорить на изучаемом
языке: «угадай занятие по значкам» и «выбери два и сравни» с опорными фразами.
- Страница: `decks/angliyskiy-5-9/activities/` (модуль кабинета 5–9).
- Контент: `data/spec.json` (руками: названия, фраза, оценки 1..3 по осям) +
  `data/photos.json` (фотобанк, `tools/python/fetch_photos.py`); сводит их
  `tools/python/build_activities.py` → `cards.json` + `fallback.js`. Сборщик
  проверяет то, что легко упустить: есть фото и кредиты, оценка в пределах 1..3,
  под каждую оценку есть файл иконки.
- Значки: **генерация** (`gen_images_openai.py`) — лист 24 иконки сеткой 4×6 на
  1024×1536, режется `slice_sheet.py` с отступом 40 px: меньший отступ тащит в
  иконку светлую рамку ячейки. Фото занятий — фотобанк, не генерация.
- Квиз по значкам: наборы оценок у двух занятий могут совпасть, и тогда у вопроса
  два верных ответа. Отвлекающие берутся только среди ДРУГИХ наборов, совпавшие
  засчитываются оба («и так тоже верно») — та же защита, что в модуле
  «Одна вещь — два слова».
- Прогресс: не пишет.

### `frazeologizmy` — «Так не бывает!» по-русски (режим речевых колод)
Русская пара к английскому `idiom`: фразеологизм показывается ДВУМЯ картинками —
сначала нелепая буквальная сцена («мальчик развешивает лапшу на уши девочке»),
потом настоящий смысл. Пара картинок вместо объяснения словами — потому что
режим рассчитан на возраст, где читают ещё плохо, а нелепость видно сразу.
- Движок: `core/engines/rech-deck-kit` (`idiomItems()` / `openIdioms()` /
  `appendIdiomBtn()`); кнопка появляется в обычной сетке и в сетке «историй».
- Вход: `DATA.idioms:[{key, phrase:"вешать лапшу на уши", lit:"буквальное
  прочтение", real:"настоящий смысл", pic_lit, pic_real,
  options:[["настоящий смысл",true],["ловушка",false]], ask:"ситуация-вопрос"}]` —
  условие показа кнопки: есть `pic_lit`, `pic_real` и `options`.
- Ход: буквальная картинка → «А что это значит?» → выбор смысла (неверный не
  пускает дальше) → настоящая картинка рядом с настоящим смыслом.
- Прогресс: не пишет (тренировочный режим).
- Эталон контента: `decks/istorii` — 6 фразеологизмов (лапша на уши, как курица
  лапой, водить за нос, держать язык за зубами, сесть в лужу, витать в облаках),
  сборка `tools/python/build_istorii_idioms.py` (ссылки на клипы переносятся по
  ключу, чтобы правка текста не сносила озвучку).
- Картинки: **только генерация**, фотобанк тут бессилен, и стиль НЕ комиксовый —
  у серии «Речь» свой вид (тёплый кремовый холст, мягкая глубина без чёрных
  рамок). Листы генерируются парами: левый столбец буквально, правый — настоящий
  смысл, персонажи в паре одни и те же.
- Озвучка: **озвучено всё, что написано** — фраза (`audio`), буквальное прочтение
  (`lit_audio`), ситуация-вопрос (`ask_audio`), настоящий смысл (`real_audio`) и
  каждый вариант (`opt_audio[]`). У каждой надписи своя маленькая ▶ (`.idmsay`),
  главная реплика экрана играет сразу при входе. Без этого режим не пройти без
  читающего взрослого — та же причина, по которой озвучены вопросы-опоры историй.
  Генератор — `tools/python/gen_istorii_idioms_tts.py` (Marina, имена клипов
  детерминированные, повторный прогон готовые не перезаписывает). Всего 42 клипа
  на 6 фразеологизмов; все 42 сверены распознаванием
  (`tools/python/check_tts_asr.py idioms`) — в клипе слышно то, что в тексте.
- **Автозапуск реплики делать «через её кнопку»**, а не `playClip(src,null)`:
  подсветка звучания достаётся бесплатно, и не надо помнить про ветку
  пауза-с-продолжением (её условие теперь требует непустой `el`).

### `idiom` — «Так не бывает!» (буквально ↔ на самом деле)
Идиома сначала читается БУКВАЛЬНО (выходит нелепость: «одолжить своё ухо»), потом
ищется настоящий смысл. Понимание переносного значения — отдельная веха развития
речи (6–8 лет), она проседает у детей с речевыми трудностями, поэтому контраст
даётся явно, а не подразумевается.
- Движок: `core/engines/eng-book` (тип упражнения `idiom`).
- Вход: `{type:"idiom", items:[{idiom:"to lend an ear", lit:"буквальное прочтение",
  options:[["настоящий смысл",true],["ловушка",false]], ex:"пример употребления",
  say:false, pic:"../img/id-ear.webp"}]}` — `lit` по-русски, `options` пары
  «текст, верно ли», `ex` опционален, `say:false` убирает кнопку озвучки идиомы,
  `pic` — картинка буквального прочтения (опционально; если файла нет, блок
  исчезает, текст остаётся). Миниатюра стоит слева от текста, по нажатию
  разворачивается во всю ширину блока — нелепость в деталях, на телефоне
  в 96 px её не разглядеть.
- **Единственное место в курсе, где картинка обязательно рисованная.** Правило
  «сначала фотобанк» здесь не работает: «одолжить своё ухо» или «заплатить носом»
  сфотографировать нельзя. Генерация — листами 6-в-1, стиль комиксов Чарли
  (жирный чёрный контур, плоская тёплая палитра), первый лист — эталон на
  утверждение владельцу.
- Проверка: выбор смысла сделан обычными `.chip.radio`, поэтому `checkEx`/`answersEx`
  работают общим кодом — отдельных веток не потребовалось.
- Прогресс: баллы = верно угаданные смыслы (по одной группе на идиому).
- Эталон контента: `decks/angliyskiy-7`, юнит 3 — пять идиом тела из методики
  Body Idioms (lend an ear, get up someone's nose, keep your nose clean,
  have a change of heart, pay through the nose).
- Русская версия для речевых колод — механика `frazeologizmy` ниже: сделана,
  6 фразеологизмов парами картинок в `decks/istorii`.

### `idiom` картинки — генерация через API
Буквальное прочтение идиомы нельзя сфотографировать, поэтому это единственное
место курса с рисованной картинкой. Раньше листы рисовались в чате по промпту и
возвращались архивом; теперь `tools/python/gen_images_openai.py` отправляет тот
же промпт в OpenAI Images и картинка сразу входит в конвейер (нарезка →
вставка → живая проверка).
- Лист 6-в-1 (1024×1536, квадратные панели 512) остаётся правилом: панели одного
  прохода держат единый стиль, отдельные вызовы разъезжаются.
- Одиночный кадр 1024×1024 — только остаток, не добивающий до полного листа,
  и точечный ремонт брака.
- Фразу «сожми в webp и выдай zip» в API-промпт НЕ ставить: она адресована
  чат-генератору с интерпретатором, а здесь попадёт в сюжет картинки.
- Строку «НИКАКОГО текста» терять нельзя: без неё генератор дописывает вывески
  (в один кадр приехала русская «КАССА» — в английский учебник).
- Собрано: 25 идиом 7 класса (3 листа + 3 одиночных кадра).

### `register` — «Скажи по-разному» (регистры речи)
Одна ситуация — три способа сказать: вежливо взрослому, обычно другу, коротко в спешке.
Это **прагматика речи и речевой этикет** (попросить, отказать, объяснить состояние) —
область, которая заметно проседает у детей с трудностями общения. Идея из таблицы
Formal / Relaxed / Informal; для детей ось переименована в адресатов.
- Движок: `core/engines/eng-book` (тип упражнения `register`).
- Вход: `{type:"register", cols:["вежливо","обычно","коротко"],
  items:[{sit:"ситуация по-русски", to:["учителю","однокласснику","совсем коротко"],
  says:["Excuse me, may I…?","Can I…?","I feel sick."]}], ask:"вопрос классу"}` —
  порядок `says` задаёт правильный регистр, `to` подпись адресата (опционально).
- Проверка: реплики раскладываются по `.slot`, поэтому `checkEx`/`answersEx` работают
  общим кодом — отдельных веток не потребовалось.
- Прогресс: баллы = верно размещённые реплики.
- Эталон контента: `decks/angliyskiy-7`, юнит 10 (выйти с урока, попросить помощь,
  отказаться от сладкого).
- ВАЖНО: исходный разворот со сленгом брать нельзя, половина примеров непечатная.
  Берётся только структура таблицы, наполнение своё.

### `myth` — «Миф или правда»
Утверждение звучит убедительно, ученик решает сам, и только после выбора открывается
объяснение. Учит проверять правдоподобное, а не запоминать готовый вывод.
- Движок: `core/engines/eng-book` (тип упражнения `myth`).
- Вход: `{type:"myth", items:[{claim:"EN утверждение", myth:true,
  truth:"разбор по-русски, почему миф или почему правда"}]}` — `myth:false` для
  верных утверждений, чтобы ответ «МИФ» не был автоматическим.
- Проверка: выбор МИФ/ПРАВДА сделан `.chip.radio`, подсчёт общий.
- Прогресс: баллы = верные решения.
- Эталон контента: `decks/angliyskiy-7`, юнит 10 — пять мифов о физкультуре
  (пот как мера усилий, всё за один раз, спорт только для умелых, силовые и объём,
  «no pain no gain»); последний пункт намеренно ПРАВДА.

### `reading` — лаборатория чтения (полный цикл разбора текста)
Один текст — весь цикл: разминка до чтения, чтение с WPM-таймером и глоссами,
проверка после. Движок — `core/engines/reading/reader.js`, контент —
`decks/<deck>/reading/data/<id>.json`, список — `data/_index.json` (+ его
встроенная копия `FALLBACK` в `index.html`, без неё офлайн-версия живёт по
старому списку).
- Вход: `{id, title, topic, lead, photohint, vocab, gloss, synonyms, sort,
  predict, passage{title, words, funfacts, paras}, comprehension, mcq, notes,
  discuss, photos}`. Секция рисуется только если поле есть — набор можно
  варьировать от текста к тексту.
- **`funfacts` — ключ это НОМЕР абзаца, с единицы**, как он подписан на экране:
  `[[2,"…"]]` встанет под вторым абзацем. Раньше движок читал ключ как индекс
  массива (с нуля): все врезки выезжали на абзац раньше, а врезка последнего
  абзаца не рисовалась вообще — при четырёх абзацах ключ `4` терялся молча
  (9 текстов 5 класса). Проверять живым прогоном, а не чтением данных.
- **`photohint`** — подсказка над фотографиями. Раньше была захардкожена под
  пилот («что это за виды спорта?») и висела над кухней, зонтом и слоном во всех
  остальных текстах. Не задал — берётся общая формулировка.
- `gloss` — трудные слова ВНУТРИ текста (пунктир + перевод по нажатию). Это НЕ
  копия `vocab`: смысл блока в поддержке там, где карточек слов не хватило.
- `sort` — разминка «как часто это делаешь ты», шкала «никогда / иногда /
  каждый день». Пункты — только действия: «как часто ты живёшь на ферме» или
  «как часто у тебя есть сестра» ответа не имеют.
- `predict` — догадка ДО чтения, `comprehension` — проверка ПОСЛЕ. Совпадать
  дословно они не должны, иначе этап догадки теряет смысл: ребёнок отвечает на
  те же утверждения дважды, уже зная ключи.
- Варианты `mcq` рисуются в порядке файла, БЕЗ перемешивания: если у всех
  вопросов `answer: 0`, ученик берёт первый вариант и получает всё верно, не
  читая. Разносить ответы по позициям — обязанность контента.
- Эталон контента и генератор с проверками: `tools/python/build_reading_g5.py`
  (5 класс, 19 текстов) — сборка падает на слове не из словника юнита, ответе
  синонима, которого нет в тексте, одинаковых ответах mcq, дубле predict ↔
  comprehension, врезке в несуществующий абзац и на грамматике выше уровня года.

### `hw` — конструктор домашнего задания
Учитель отмечает упражнения любого юнита — внизу собирается ссылка `?hw=id,id,…`
для класса; у ученика открывается только эта выборка, с самопроверкой и кодом
результата в конце. Плюс готовые наборы по уровням (база / стандарт / вызов /
билетик на выход) на каждый юнит.
- Движок: `core/engines/eng-book/hw.js` + `hw.css`. Раньше и логика, и стили
  лежали ВНУТРИ `decks/angliyskiy-5/teacher/hw.html` — из-за этого конструктора
  не было у 6 и 7 классов: скопировать страницу значило форкнуть логику на три
  колоды (запрещено правилом разделения).
- Колода даёт только свои данные, тонкой страницей `teacher/hw.html`:
  `window.HW_CONFIG = {manifest:['../data/unit1.json', …], extra:['../data/bank-*.json']}`.
  `manifest` берётся из `window.BOOK_MANIFEST` учебника той же колоды — списки
  не разъезжаются.
- Готовые наборы: `teacher/hw-variants.json`, генератор
  `tools/node/gen-hw-variants.js <deck>` — раскладывает упражнения юнита по
  уровням по типу механики (узнавание / применение / продукция).
- Проверка: страница открывается, число готовых наборов равно длине
  `hw-variants.json`, упражнения всех юнитов перечислены. Живым прогоном:
  5 класс — 29 наборов, 6 и 7 — по 15.
